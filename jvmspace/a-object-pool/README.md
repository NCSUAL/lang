## 요구사항

생성 비용이 큰 객체를 매번 새로 생성하지 않고 재사용할 수 있는 **Object Pool**을 구현한다.

### 객체 대여

- 사용 가능한 객체가 존재하면 해당 객체를 반환한다.
- 사용 가능한 객체가 없고 최대 객체 수에 도달하지 않았다면 새 객체를 생성한다.
- 최대 객체 수에 도달했다면 객체가 반환될 때까지 기다린다.
- 설정된 대기 시간이 지나면 예외를 발생시킨다.

```text
borrow()

   ↓

Idle 객체 존재?
 ├─ Yes → 객체 반환
 └─ No
      ↓
   새 객체 생성 가능?
    ├─ Yes → 생성 후 반환
    └─ No  → 반환될 때까지 대기
```

### 객체 반환

- 사용이 끝난 객체를 Pool에 반환할 수 있다.
- 반환된 객체가 정상인지 검사한다.
- 정상 객체는 다시 재사용한다.
- 비정상 객체는 폐기한다.

```text
ACTIVE → release → validate

                    ├─ 정상 → IDLE
                    └─ 비정상 → DESTROYED
```

### 객체 폐기

- 사용 중 문제가 발생한 객체를 명시적으로 폐기할 수 있다.
- 폐기된 객체는 다시 대여할 수 없다.

### Pool 설정

다음 설정을 지원한다.

- 최대 객체 수
- 최소 유휴 객체 수
- 객체 대기 시간

잘못된 설정 값으로 Pool을 생성할 수 없다.

### 객체 생성 책임 분리

Pool이 관리할 객체의 생성 방법을 직접 알아서는 안 된다.

별도의 Factory를 통해 다음 기능을 제공한다.

- 객체 생성
- 객체 상태 검증
- 객체 폐기

### 자원 자동 반환

대여한 객체는 `try-with-resources`로 사용할 수 있어야 한다.

작업 중 예외가 발생하더라도 객체가 자동으로 Pool에 반환되어야 한다.

### Pool 종료

- Pool을 명시적으로 종료할 수 있다.
- 종료 시 대기 중인 객체를 모두 폐기한다.
- 종료된 Pool에서는 새로운 객체를 대여할 수 없다.

---
- Java 표준 JDK만 사용한다.
- Spring, Lombok 등의 외부 프레임워크를 사용하지 않는다.
- Java 코드 컨벤션을 지킨다.
- indent depth는 최대 2까지만 허용한다.
- 메서드는 한 가지 역할만 수행하도록 작게 분리한다.
- 객체의 상태를 `null`로 표현하지 않는다.
- 잘못된 상태의 객체가 생성되지 않도록 생성 시점에 검증한다.
- `finalize()`와 `Cleaner`를 사용하지 않는다.
- 자원 반환이 필요한 객체는 `AutoCloseable`을 활용한다.
---

## 📌 객체 상태

Pool의 객체는 다음 상태를 가진다.

```text
        borrow
IDLE ───────────→ ACTIVE
 ↑                  │
 │                  │ release
 └──────────────────┘

ACTIVE ── invalidate ──→ DESTROYED
```

## 📈 구현

기본 기능을 완료한 경우 다음 기능을 구현한다.

- 여러 Thread에서 동시에 객체 대여 및 반환
- 최대 객체 수 초과 방지
- 대기 중인 Thread 처리
- Idle 객체 자동 정리
- Pool 상태 조회
    - 전체 객체 수
    - 사용 중 객체 수
    - 대기 객체 수
